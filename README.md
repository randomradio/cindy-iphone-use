# iPhone Use for Cindy

Cindy adapter for [iPhone-use](https://github.com/zhongerxin/iPhone-use) 0.3.6. It connects to an existing local Phone Use Agent (PUA) service; the vendored Python modules retain upstream licensing. Official-plugin positioning is tracked in [makecindy/cindy-official-plugins#230](https://github.com/makecindy/cindy-official-plugins/issues/230).

The right panel works on desktop and declares the same self-contained HTML for mobile. A panel BroadcastChannel talks to main.js, which calls Cindy's bundled Node worker. The worker keeps one Python MCP server alive and preserves the upstream PUA state/session/operation lock behavior. Frames are UI-only, pulled at a target interval of 250 ms; mobile messages carry at most 24 KiB of frame text at a time. Hidden pages stop polling; the upstream five-second lease stops capture. Pausing immediately clears pixels and sets the shared authentication pause. Resume/Refresh is an explicit user action.

Node's native permission is required: the worker starts `python3`, reads existing private PUA configuration, and the upstream preview starts a standalone `node` from PATH. Home changes the phone. Screenshot copies to the **connected Mac clipboard**, including when clicked from Cindy on iPhone; it does not copy to the mobile clipboard. Model tools can observe and perform the explicitly declared phone actions. Cindy media deposit permission delivers requested model screenshots as media URLs, with local `image.path` fallback if import fails. Frames never use deposit and are never tool results.

## Requirements and boundaries

- macOS, an existing configured and running PUA/WDA service, Python 3 and standalone Node. PATH includes inherited entries plus `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin` and `/bin`.
- The existing PUA state must contain `runtime/forward/node_modules/appium-ios-device`. No install, npm, WDA build, start, recovery or configuration endpoint is exposed. The Python and stream helper source are bundled; the existing USB dependency installation is reused.
- Upstream state resolution remains `IPHONE_USE_STATE_DIR`, `WDA_STATE_DIR`, `~/.local/share/iphone-use`, then the legacy `iphone-use-wda` directory when applicable.
- `adapter_status` inspects local configuration presence, bridge state and sandbox-held `panel` telemetry. `panel.seen` and `panel.instances` distinguish a loaded panel from no heartbeat received; each instance includes heartbeat age/connection freshness, desktop/mobile source, visibility/pause state, decoded natural dimensions, last draw time/sequence, last poll time and bounded error codes/counts. Heartbeats run on load/decode, visibility changes and every five seconds (including while paused). No pixels, URLs or raw error text are retained. A heartbeat/decode reports browser state, not independent proof of physical display or current phone contents; hidden/suspended pages can become stale. This status call does not spawn Python, contact the phone or test PUA readiness.
- The action receipt ledger lives in `~/.local/share/cindy-iphone-use/requests.json`, mode 0600. It contains request hashes and receipts, never text, selectors or images. Same-ID writes are not replayed, including across worker restart. It fails closed after 512 entries; review/clear this private ledger before exceeding that limit. An unknown outcome blocks new mutations until a fresh successful observation after the pending call resolves. New tool-call IDs represent new user/Agent operations; do not reissue uncertain actions with a new ID.
- Preview transfers are memory-only, expire after 30 seconds, have a maximum of four concurrent transfers and an 8 MiB limit. Mobile assembly has a 15-second deadline. Model image transfers have a separate scope that the UI cannot select.
- Native screenshot evidence is retained by upstream in its private state directory; explicit observation images deposited in Cindy use its normal media lifecycle. Upstream server stderr is drained and suppressed, and frames are never logged by adapter code.
- Only English and simplified Chinese UI are provided; `/app-context` chooses the locale and unsupported locales fall back to English. Theme colors use Cindy variables.

## Build and verification

`python3 -B build.py` copies the exact supported parameter schemas from bundled upstream code into `ghost.json`; it imports definitions without creating a Runtime or touching a device. `node --test tests/*.test.cjs` runs mock-only routing, timeout, chunk size, isolation, deduplication and panel lifecycle tests.

The manifest targets Cindy **0.1.115**, verified from the locally installed app (`CFBundleShortVersionString`). This is the local validation target; the earliest release supporting every used capability has not been independently established. Confirm compatibility before official distribution.

Run `node --test tests/*.test.cjs` and `python3 -B build.py` after changes to upstream schemas. `ghost_forge_pack` validated and packaged the local source as `iphone-use-panel-0.1.0.cindy`; packages are generated artifacts and are excluded from Git. A local Cindy install and desktop panel test on a paired physical iPhone confirmed decoded 1242 × 2688 frames with successive displayed sequence numbers and zero panel errors. Agent `ready` and explicit screenshot observation also succeeded. The mobile remote panel has not been independently tested on a physical iPhone; an official release still requires its own packaged-build verification and maintainer review.
